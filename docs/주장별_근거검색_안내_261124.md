# VeriFive 주장별 근거 검색 작업본 안내

날짜: 2026-11-24

## 1. 이번 작업의 목적

기존 방식은 질문 전체를 한 번 임베딩해 유사한 청크를 검색했습니다. 복합 질문에서는 일부 주장의 근거만 검색되어도 답변이 생성될 수 있어, RAG가 무슨 역할을 하는지 드러나기 어려웠습니다.

이번 작업본은 **최신 웹 기사 수집을 유지하면서 질문을 개별 주장으로 나누고, 주장마다 근거 문단을 별도로 검색**합니다. RAG의 역할을 DB 재사용이 아니라 **주장별 근거 선택과 출처 추적**으로 명확히 합니다.

## 2. 실행 파일

- `claim_evidence.py`: 새로 추가한 주장별 검색 셀과 동일한 코드

## 3. 바뀐 처리 순서

```text
질문 입력
  ↓
네이버 뉴스 웹 검색·최신 기사 수집  ← 같은 질문을 다시 입력해도 다시 수행
  ↓
기사 정제 → 청킹 → 임베딩 → 벡터 DB 저장  ← 기존 로직 유지
  ↓
질문을 최대 4개의 개별 주장으로 분해
  ↓
주장마다 상위 근거 청크 2개씩 벡터 검색
  ↓
주장별 검색 결과를 표시하고 중복 청크를 제거
  ↓
기존 RAGGenerator로 답변 생성 및 출처 표시
```

## 4. 수정 내용과 필요한 이유

### 가. 같은 질문의 웹 재수집 캐시 제거

기존 UI는 같은 질문이면 이전 수집 결과를 재사용했습니다. 뉴스 팩트체크에서는 같은 질문 사이에도 새 보도가 나올 수 있으므로, 이 캐시를 답변 경로에서 제거했습니다. 최신성을 유지하기 위한 변경입니다.

### 나. `ClaimEvidenceRetriever` 추가

기존 `VectorSearchManager`를 재사용해 주장별로 검색합니다. 새 검색 엔진이나 DB로 교체하지 않으므로 기존 청킹·임베딩·FAISS 저장 방식은 그대로입니다.

### 다. 주장별 검색 결과 표시

각 주장에 대해 다음을 표시합니다.

- 개별 주장
- 근거 검색됨 / 근거 부족
- 검색된 근거 수
- 근거 기사 제목·언론사·발행일·URL·유사도

유사도는 **관련 문단을 찾는 점수일 뿐 참·거짓 판정값이 아닙니다.** ‘근거 검색됨’도 실제 사실 확인이 아니라 유사도 기준을 넘는 문단이 검색됐다는 뜻입니다.

### 라. 생성 프롬프트에 주장 연결 표시

각 청크가 어떤 주장을 검색하기 위해 선택됐는지 프롬프트에 함께 제공합니다. 한 주장의 근거를 다른 주장에 임의로 적용하지 않도록 지시를 추가했습니다.

## 5. Colab에서 확인할 순서

1. 작업본을 열고 기존과 동일한 순서로 패키지·수집·전처리 셀을 실행합니다.
2. 추상화 메서드 구간의 클래스들을 실행합니다.
3. 새로 추가된 **CELL 27 `ClaimEvidenceRetriever`** 셀을 실행합니다.
4. `RAG LOAD`와 UI 파이프라인 셀을 기존 순서대로 실행합니다.
5. UI에서 다음 복합 질문을 입력합니다.

   `젠슨 황이 엔비디아에서 퇴사하고 테슬라에 입사했다`

6. 결과창에 **주장별 근거 검색** 영역이 나타나는지 확인합니다.
7. 두 주장이 따로 표시되고 각 주장의 기사·발행일·유사도가 보이는지 확인합니다.
8. 같은 질문을 다시 실행해 웹 수집 단계가 다시 진행되는지 확인합니다.
9. 단일 질문도 입력해 기존 답변 경로가 유지되는지 확인합니다.

   `컨닝 전문 조직이 있어?`

## 6. 완료된 검증

### 로컬

- 주장 분해·근거 검색·중복 제거 단위 테스트 10개 통과
- 노트북 연동 검증 16개 통과, `nbformat` 검사 1개는 미설치로 생략
- 수정 셀 Python 문법과 UI JavaScript 문법 검사 통과
- 같은 질문 두 번 실행 시 웹 수집 두 번 호출 확인
- 계획된 기존 셀 5개만 수정하고 새 셀 1개를 추가했는지 확인

### 실제 Colab L4

- 네이버 API 보안 비밀 두 개의 노트북 접근 권한을 연결하고 실제 뉴스 수집 확인
- 복합 질문을 `엔비디아 퇴사`와 `테슬라 입사` 두 주장으로 분리하고 각각 기사·발행일·유사도 표시 확인
- 최초 실행에서는 관련 기사 공동 등장을 이유로 `테슬라 입사`까지 인정하는 오류가 있어, 주장별 후보 연결과 핵심 행위의 직접 명시를 요구하는 생성 지시를 추가
- 같은 질문을 다시 웹 수집한 최종 실행에서는 `엔비디아 퇴사는 확인 / 테슬라 입사는 근거 부족`으로 답변 확인
- 단일 질문 `컨닝 전문 조직이 있어?`도 실제 기사 3건 수집, 주장 1개 검색, RAG·일반 LLM 답변과 출처 표시 확인
- vLLM 0.31.0 모델 적재, 벡터 DB 폴터 자동 생성, ngrok 실패 시 Colab 프록시 전환, 결과창 자동 표시 수정 확인

주장별 목록의 `근거 검색됨`은 **후보 문단 검색**이라는 뜻이며, 최종 지지 여부는 생성 답변에서 다시 판단합니다.

## 7. 현재 한계

- 주장 분해는 추가 LLM 호출 없이 동작하는 보수적 규칙 기반입니다. 접속 표현이 없는 복합 주장은 하나로 남을 수 있습니다.
- `하고`는 ‘발전하고 있다’처럼 단순 동작 연결을 잘못 자르지 않도록 다음 절의 대상·조사가 보일 때만 분리합니다.
- 주장별 상위 2개 청크를 검색하며, RAG 입력은 기본 최대 8개입니다. 각 주장의 최상위 근거 하나는 우선 보존합니다.
- 기사 간 모순과 최종 사실 여부는 생성 모델이 근거를 바탕으로 설명하며, 벡터 유사도가 자동으로 진위를 판정하지는 않습니다.

## 8. 발표용 설명

> 최신성은 매 질문의 웹 수집으로 유지하고, RAG는 수집된 기사 안에서 복합 질문의 개별 주장에 대응하는 근거 문단을 찾는 데 사용했습니다. 따라서 웹 검색은 최신 기사 확보를, RAG는 주장별 근거 선택과 출처 추적을 담당합니다. 결과 화면에서도 주장별 근거와 근거 부족을 구분해 보여주도록 구현했습니다.
